# Railway Deployment Guide

This guide explains how to deploy Wissen-Haus on Railway and configure all required environment variables.

## Architecture

The Wissen-Haus application consists of two services:
- **API**: Express.js backend server (Node.js)
- **Web**: Next.js frontend application (Node.js)

Both services must be deployed as separate services on Railway with separate public domains.

## Deployment Steps

### 1. Create a New Railway Project

1. Go to [Railway.app](https://railway.app)
2. Click "New Project"
3. Connect your GitHub repository (fawazzzbello/wissen-haus)

### 2. Create Services

You need to create two separate services:

#### Service 1: API
1. Add a new service → Select "GitHub Repo"
2. Configure with:
   - **Root Directory**: `apps/api`
   - **Build Command**: `npm run build -w apps/api`
   - **Start Command**: `npm run start -w apps/api`
   - **Port**: 5000

#### Service 2: Web
1. Add a new service → Select "GitHub Repo"
2. Configure with:
   - **Root Directory**: `apps/web`
   - **Build Command**: `npm run build -w apps/web`
   - **Start Command**: `npm run start -w apps/web`
   - **Port**: 3000

### 3. Add Database

1. Click "Add" → Select "PostgreSQL"
2. This will automatically add `DATABASE_URL` environment variable

### 4. Configure Environment Variables

Set the following environment variables in your Railway project:

#### API Service Variables

```
# Database (auto-generated by Railway PostgreSQL plugin)
DATABASE_URL=postgresql://user:password@host:port/database

# Or use individual database variables
DB_HOST=your-railway-db-host
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=your-password
DB_NAME=wissen_haus_db

# Server Configuration
NODE_ENV=production
PORT=5000
FRONTEND_URL=https://your-web-domain.railway.app

# SendGrid Email Service
SENDGRID_API_KEY=SG.your_actual_api_key_here
SENDGRID_FROM_EMAIL=noreply@wissen-haus.org
SENDGRID_FROM_NAME=Wissen-Haus

# Stripe Payment Processing
STRIPE_PUBLIC_KEY=pk_live_your_key_here
STRIPE_SECRET_KEY=sk_live_your_key_here
STRIPE_WEBHOOK_SECRET=whsec_your_key_here

# Twilio SMS (Optional)
TWILIO_ACCOUNT_SID=your_account_sid
TWILIO_AUTH_TOKEN=your_auth_token
TWILIO_PHONE_NUMBER=+1234567890

# Contact Form
CONTACT_FORM_RECIPIENT_EMAIL=admin@wissen-haus.org
```

#### Web Service Variables

```
# API Configuration
NEXT_PUBLIC_API_URL=https://your-api-domain.railway.app/api
NEXT_PUBLIC_STRIPE_PUBLIC_KEY=pk_live_your_key_here

# Server Port
PORT=3000
```

## Important Configuration Notes

### Database Connection

- **Option 1 (Recommended)**: Use `DATABASE_URL` provided by Railway's PostgreSQL plugin
  - Railway automatically sets this when you add PostgreSQL
  - The API will automatically parse this variable

- **Option 2**: Use individual database variables
  - Set `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`
  - Useful if using external database

### Port Configuration

- Railway automatically assigns ports. The `PORT` environment variable will be set by Railway
- Do NOT hardcode ports in environment variables
- The API service will listen on the assigned PORT (usually 5000)
- The Web service will listen on the assigned PORT (usually 3000)

### Frontend URL

The API needs to know the frontend URL for CORS configuration:
- `FRONTEND_URL` in API service should point to your web app's Railway domain
- Example: `https://wissen-haus-web.railway.app`

### API URL in Frontend

The web app needs to know the API URL:
- `NEXT_PUBLIC_API_URL` should point to your API service's Railway domain + `/api`
- Example: `https://wissen-haus-api.railway.app/api`

## Troubleshooting

### EADDRINUSE Error (Port Already in Use)

**Problem**: Port 5000 is already in use
**Solution**: 
- Ensure API and Web are separate services with separate domains
- Don't run both services on the same Railway service
- Each service should have its own Railway deployment

### Database Connection Refused

**Problem**: Cannot connect to PostgreSQL
**Solution**:
1. Verify PostgreSQL plugin is added to the project
2. Check `DATABASE_URL` or individual `DB_*` variables are set
3. Make sure database is running: Check Railway dashboard for service status
4. Restart the API service after adding/modifying database variables

### SendGrid API Key Error

**Problem**: "API key does not start with 'SG.'"
**Solution**:
1. Verify SENDGRID_API_KEY starts with "SG."
2. Use valid SendGrid API key from SendGrid dashboard
3. Email functionality is optional - service will warn but continue without it
4. To disable email notifications, simply don't set SENDGRID_API_KEY

### npm Warnings

**Problem**: "npm warn config production Use `--omit=dev` instead"
**Solution**: This is automatically handled by `.npmrc` configuration. Railway should use the correct npm commands.

## Environment Variable Checklist

Before deploying, ensure you have:

- [ ] Database connection (DATABASE_URL or DB_* variables)
- [ ] NODE_ENV=production
- [ ] FRONTEND_URL pointing to web service
- [ ] NEXT_PUBLIC_API_URL pointing to API service + /api
- [ ] SENDGRID_API_KEY (optional, but needed for emails)
- [ ] STRIPE_* keys (if using Stripe for donations)
- [ ] All other service API keys as needed

## Service Health Checks

Both services have health check endpoints:

### API
```
GET /health
Response: {"status":"ok","timestamp":"...","environment":"production"}
```

### Web
```
GET / (or any page)
Returns Next.js page
```

## Monitoring

After deployment, monitor:
1. Service logs for any startup errors
2. Database connection status
3. API response times
4. Email delivery (if using SendGrid)

## Rollback

If deployment fails:
1. Go to Railway dashboard
2. View deployment history
3. Redeploy previous version
4. Check logs for specific errors
